# tnt-clock

Часы и пауза для Tarantool, пригодные к подмене в проверках: монотонные
часы для длительности и срока, время планировщика для остатка срока,
наносекунды для метрик, стенные часы для даты и пауза файбера.

```lua
local clock = require('tnt.clock')

local started = clock.monotonic()                -- длительность
local elapsed = clock.monotonic() - started

local deadline = clock.monotonic() + timeout     -- срок — миг вызова
cond:wait(deadline - clock.scheduler_now())      -- остаток — в ожидание
```

Зависимостей нет: только `clock` и `fiber` из Tarantool.

## Зачем

Монотонных часов в Tarantool двое: настоящие `clock.monotonic()`
и отметка цикла событий `fiber.clock()`. Разница не видна, пока файбер
не займётся работой, не уступая управления, — а тогда по отметке работа
занимает ноль, и срок, отмеченный ею, отсчитан от последней уступки,
а не от вызова. Пакет делает три вещи:

- **Называет часы по назначению.** `monotonic` — длительность и миг
  срока; `scheduler_now` — остаток срока, который уходит в сон или
  ожидание: `fiber.sleep` и `cond:wait` отсчитывают срок от той же
  отметки, и остаток по ней кончается ровно в срок.
- **Даёт умолчания, пригодные к подмене.** Все пять — функции без
  состояния: модуль кладёт их в свою таблицу зависимостей, а проверка
  подставляет свои, и минутный срок истекает мгновенно.
- **Держит правило выбора в одном месте.** Замеры и следствия — в шапке
  модуля; в коде остаются только отступления, каждое с комментарием.

## Установка

```sh
tt rocks install tnt-clock --server=https://tnt-skein.github.io/rocks
```

Или из исходников:

```sh
git clone https://github.com/tnt-skein/tnt-clock.git
cd tnt-clock && tt rocks make
```

## Как пользоваться

| Функция | Что возвращает | Для чего |
|---|---|---|
| `monotonic()` | секунды от загрузки машины | длительность и миг срока |
| `scheduler_now()` | секунды от той же точки, отметка цикла событий | остаток срока, уходящий в ожидание |
| `monotonic64()` | наносекунды `int64` от той же точки | метрики |
| `realtime()` | секунды от начала эпохи | дата в отчёте и журнале |
| `sleep(seconds)` | — | пауза файбера |

Срок — миг, и отмечается он настоящими часами в миг вызова; истёк ли
он, решают тоже они. Остаток, уходящий в ожидание, считается от времени
планировщика:

```lua
local deadline = clock.monotonic() + timeout

while not ready() do
    if clock.monotonic() >= deadline then
        return nil, 'срок истёк'
    end

    cond:wait(deadline - clock.scheduler_now())
end
```

Стенные часы — только для даты: их двигает перевод времени, и ни
длительность, ни срок по ним не меряют. `monotonic64` — те же
монотонные часы целым числом наносекунд: секунды в `double` теряют
наносекунды на сервере, проработавшем дольше 97 суток.

## Проверки

```sh
make deps          # luatest, luacheck и luacov в .rocks
make check         # форматирование, линт, проверки, покрытие с порогом 100 %
make mutants-all   # мутационное тестирование утилитой tnt-mutants из PATH, порог 100 % убитых
```

Покрытие строк — 100 %, убитых мутантов — 100 % (мутанта четыре:
у обёрток мутируется только возврат). Двойников часов в проверках
нет намеренно: перепутанный источник времени заметен только
на настоящем ядре и на работе без уступки, и проверки построены на ней.
